# 验证计划

## 1. 验证目标

从公开接口确认选择逻辑、状态推进、复位行为、接口不变量和轮询公平性满足规格，并证明检查器能够检出已知状态更新故障。

## 2. 验证方法

| 方法 | 目的 |
|---|---|
| RTL 静态检查 | 检查语法、位宽、未使用信号和组合/时序编码告警 |
| 独立参考模型 | 根据请求向量和模型起点计算预期授权 |
| 穷举状态/输入交叉 | 覆盖 4 个起点与 16 个请求向量的全部 64 种组合 |
| 黑盒下一状态探针 | 使用 `req=1111` 从授权结果反推出 DUT 的当前起点 |
| 持续请求公平性 | 覆盖 4 个起点与 15 个非空请求集合，共 60 个场景 |
| 接口不变量检查 | 检查独热、请求授权一致性和非空请求不丢失 |
| SVA | 在时钟边沿持续检查四条接口性质 |
| 故障注入 | 证明错误回卷状态不能逃逸回归 |

DUT = Design Under Test，被测设计。

SVA = SystemVerilog Assertions，SystemVerilog 断言。

## 3. 独立性原则

测试平台不得读取内部轮询指针。参考模型使用循环索引计算预期授权，与 DUT 的四分支 `case` 实现不同。状态正确性通过公开 `grant` 端口和全请求探针检查，避免白盒层次引用把验证绑定到实现细节。

## 4. 检查器

每个有效测试周期执行：

1. 实际授权与参考模型逐位比较；
2. 授权为全零或独热编码；
3. 授权位必须属于请求向量；
4. 空请求必须零授权，非空请求必须非零授权。

复位场景分别在异步复位生效后和跨过一个时钟边沿后检查零授权。公平性场景累计一个服务窗口内的授权集合，并与持续请求集合比较。

## 5. 断言

| 性质 | 预期 |
|---|---|
| `p_reset_blocks_grant` | 复位期间授权为零 |
| `p_grant_is_onehot0` | 授权全零或独热 |
| `p_grant_has_request` | 不授权未请求者 |
| `p_nonempty_request_gets_grant` | 非空请求必有授权 |

## 6. 故障注入

在临时 RTL 副本中，把“起点为 2 且请求者 3 获授权”后的下一起点由 0 改为 1。正向回归必须失败，并出现参考模型授权不匹配；故障注入脚本只有在故障被正确检出时才返回成功。

## 7. 退出标准

- Verilator 严格 RTL 静态检查零设计告警；
- 64/64 状态/请求交叉全部通过；
- 64/64 下一状态探针全部通过；
- 60/60 持续请求公平性场景全部通过；
- 1,712 次自动比较零错误；
- 四条 SVA 零失败；
- 已知错误回卷故障被自动检出；
- `make verify` 可从干净工作区重复执行。
