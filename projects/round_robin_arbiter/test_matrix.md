# Round-robin Arbiter Test Matrix

| 测试编号 | 输入或前置条件 | 主要预期 | 检查重点 | 状态 |
|---:|---|---|---|---|
| 1 | 复位，`req=1111` | `grant=0000`，指针为 0 | 异步复位 | 通过 |
| 2 | 指针 0，`req=0000` | 不授权，指针保持 0 | 空闲保持 | 通过 |
| 3-6 | 四个单独请求依次出现 | 授权对应请求，指针移到后一位 | 单请求与回卷 | 通过 |
| 7-11 | `req=1111` 持续有效 | 0、1、2、3、0 轮转 | 公平性与回卷 | 通过 |
| 12 | 第二次复位 | 授权和指针清零 | 状态恢复 | 通过 |
| 13 | 指针 0，`req=0010` | 授权 1，下一指针为 2 | 跳过请求者 0 | 通过 |
| 14-17 | 指针 2，`req=1011` 持续有效 | 3、0、1、3 | 稀疏请求、跳过、回卷 | 通过 |
| 18 | 第三次复位 | 授权和指针清零 | 重复复位 | 通过 |
| 19 | `req=0010` | 指针移动到 2 | 测试前置状态 | 通过 |
| 20-21 | 指针 2，连续 `req=0000` | 连续保持指针 2 | 无请求保持 | 通过 |

所有非复位数据场景还会自动执行：

- one-hot 检查；
- `grant` 只能出现在有效 `req` 位上的合法性检查；
- 上升沿后的下一指针检查。

one-hot = 独热编码，多个位中最多只有一位有效。
