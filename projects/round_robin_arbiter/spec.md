# Round-robin Arbiter Specification

> 状态：规格、RTL、testbench 和 21 项定向仿真已完成  
> 日期：2026 年 8 月 1 日

## 1. 模块目标

设计一个四请求者 round-robin arbiter（轮询仲裁器）。当多个请求者争用同一个资源时，模块每次最多授权一人，并让持续请求者轮流获得服务，避免固定优先级导致的长期饥饿。

arbiter = arbiter，仲裁器。  
round-robin = 轮询调度。  
RTL = Register Transfer Level，寄存器传输级。  
testbench = 测试平台 / 测试代码。

## 2. 接口

| 信号 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| `clk` | input | 1 | 时钟，上升沿更新轮询起点 |
| `rst_n` | input | 1 | 低电平有效复位 |
| `req` | input | 4 | 四个请求者的请求信号 |
| `grant` | output | 4 | 四个请求者的授权信号，最多一位为 1 |

input = 输入。  
output = 输出。  
request = 请求。  
grant = 授权。

位映射：

```text
req[0] / grant[0]：请求者 0
req[1] / grant[1]：请求者 1
req[2] / grant[2]：请求者 2
req[3] / grant[3]：请求者 3
```

## 3. 状态定义

模块保存一个两位轮询起点 `priority_ptr`：

```text
priority_ptr = 0：从请求者 0 开始检查
priority_ptr = 1：从请求者 1 开始检查
priority_ptr = 2：从请求者 2 开始检查
priority_ptr = 3：从请求者 3 开始检查
```

pointer = 指针；这里表示下一次优先从谁开始检查。

## 4. 功能规则

1. 复位有效时，`grant = 4'b0000`，轮询起点恢复为请求者 0。
2. 复位解除后，按照 `priority_ptr` 指定的位置开始检查请求。
3. 检查到请求后立即停止搜索，只授权第一个找到的请求者。
4. `grant` 必须是 one-hot（独热编码）或全零，每次最多一位为 1。
5. 不得授权 `req` 中没有请求的人，即 `grant` 只能出现在 `req` 为 1 的位置。
6. 没有任何请求时，`grant = 4'b0000`，`priority_ptr` 保持不变。
7. 成功授权请求者 0 后，下一次从请求者 1 开始。
8. 成功授权请求者 1 后，下一次从请求者 2 开始。
9. 成功授权请求者 2 后，下一次从请求者 3 开始。
10. 成功授权请求者 3 后，下一次回到请求者 0。
11. 第一版把每次非零 `grant` 视为本周期服务成功，不加入额外握手信号。

one-hot = 独热编码，多个位中最多只有一位有效。

## 5. 组合逻辑与时序逻辑

组合逻辑负责：

- 读取当前 `req`；
- 从 `priority_ptr` 开始按轮询顺序搜索；
- 生成当前 `grant`；
- 计算下一次轮询起点。

时序逻辑负责：

- 在时钟上升沿保存下一次轮询起点；
- 复位时把轮询起点恢复为 0。

第一版的 `grant` 是组合输出，不额外增加一级输出寄存器。

## 6. 典型行为

### 所有人持续请求

复位后 `priority_ptr = 0`，`req = 4'b1111`：

```text
第 1 次：grant = 0001，请求者 0
第 2 次：grant = 0010，请求者 1
第 3 次：grant = 0100，请求者 2
第 4 次：grant = 1000，请求者 3
第 5 次：grant = 0001，请求者 0
```

### 稀疏请求和回卷

`priority_ptr = 2`，`req = 4'b1011`：

```text
检查顺序：2 → 3 → 0 → 1
授权顺序：3 → 0 → 1 → 3
grant：1000 → 0001 → 0010 → 1000
```

## 7. 公平性要求

在第一版“每次授权都成功”的假设下，只要某个请求者持续保持请求，并且模块持续运行，它必须在最多四次授权机会内获得一次服务。

公平不表示严格按照编号机械轮流。如果某个请求者没有请求，仲裁器必须跳过它。

## 8. 测试点

| 编号 | 场景 | 预期结果 |
|---:|---|---|
| 1 | 复位 | `grant=0000`，轮询起点为 0 |
| 2 | 无请求 | `grant=0000`，轮询起点保持 |
| 3 | 仅请求者 0 请求 | `grant=0001` |
| 4 | 仅请求者 1 请求 | `grant=0010` |
| 5 | 仅请求者 2 请求 | `grant=0100` |
| 6 | 仅请求者 3 请求 | `grant=1000` |
| 7 | 四人持续请求 | 授权按 0、1、2、3 循环 |
| 8 | `priority_ptr=2` 且 `req=1011` | 授权按 3、0、1、3 轮转 |
| 9 | 请求者缺席 | 跳过未请求者，不产生空授权 |
| 10 | 回卷 | 服务请求者 3 后从请求者 0 重新开始 |
| 11 | one-hot 检查 | `grant` 不得同时出现两个或更多的 1 |
| 12 | 合法性检查 | `(grant & ~req)` 必须为 0 |
| 13 | 公平性检查 | 持续请求者在最多四次授权内得到服务 |
| 14 | 请求变化 | 新请求按当前轮询起点参与下一次选择 |

## 9. 暂不包含

第一版不包含：

- 参数化请求者数量；
- `valid-ready` 握手；
- 授权接受或拒绝；
- 固定优先级覆盖；
- 多个资源同时授权；
- 跨时钟域请求。

valid-ready = 有效-就绪握手机制。  
CDC = Clock Domain Crossing，跨时钟域。

这些内容在完成四请求者基础版本后再扩展。
