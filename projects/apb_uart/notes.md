# 第一课：把 APB 规则变成代码

**简体中文** | [English](notes.en.md)

## 一句话

请求出现，不等于寄存器已经写入；只有完成且合法的写请求才能改数据。

```systemverilog
if (psel && penable && pready && pwrite && !bad_access)
    data_reg <= pwdata;
```

这段位于时钟上升沿触发的 `always_ff` 中。前三个条件表示传输完成，后两个表示合法写。复位优先级更高。

## 文件分工

- RTL：真实被测电路，保存数据，产生响应。
- testbench（测试平台）：模拟访问方，发送读写，计算正确结果并比较。
- expected：测试侧记住的正确值，不是从电路内部抄来的答案。
- 内部信号检查：额外观察 DATA 是否提前变化，属于白盒检查。

## 最容易混淆

- `PREADY=1` 不是单独的完成条件，还必须在选中后的访问阶段和时钟上升沿判断。
- `PSLVERR=1` 表示这笔传输完成但报错，不是继续等待。
- 数据在等待中必须保持，不代表可以每拍都执行一次写操作。
- 测试通过证明已测场景符合规格，不证明所有情况都正确。
