# 架构说明

## 数据流

```text
req[3:0] ──> 带回卷的优先搜索 ──> grant[3:0]
                   ▲                  │
                   │                  │ 非零授权
                   │                  ▼
              priority_ptr <── 下一起点计算
                   ▲
                   └── 时钟上升沿更新 / 异步复位清零
```

`grant` 是组合输出，`priority_ptr` 是模块唯一状态。组合逻辑同时计算当前授权和下一起点，时序逻辑只保存起点。

## 搜索与回卷

轮询指针不是“上一次授权者编号”，而是“本轮第一个检查的位置”。例如起点为 2 时，搜索顺序为 2、3、0、1。若请求向量为 `1011`，请求者 2 没有请求，因此首先授权请求者 3，下一轮从 0 开始。

## 接口取舍

当前模块没有 `accept` 或 `ready` 输入，因此默认非零授权在当前周期内完成服务。这个假设使接口适合教学、小型单周期资源选择和验证方法展示，但不适合资源可能拒绝请求的场景。

接入带反压资源时，应把状态更新条件改为：

```text
grant_valid && grant_accepted
```

只有握手完成才能推进轮询起点，否则必须保持当前状态。

## 验证架构

测试平台把内部状态当作不可见实现细节：

```text
定向激励 ──> DUT ──> grant ──> 自动比较
    │                            ▲
    └──> 独立参考模型 ───────────┘
```

参考模型使用循环索引，DUT 使用明确的四分支搜索。不同实现方式降低了同类编码错误同时出现在设计和预期模型中的风险。下一状态通过 `req=1111` 的黑盒探针观察，而不是层次读取内部寄存器。

DUT = Design Under Test，被测设计。
