# Round-robin Arbiter Verification Plan

## 1. 验证目标

确认四请求者轮询仲裁器在复位、单请求、多请求、稀疏请求和无请求场景下满足规格，并能保持授权合法性与轮询公平性。

## 2. 验证范围

本阶段验证：

- 低电平有效异步复位；
- 全零或 one-hot 授权；
- 只授权有效请求者；
- 从当前指针开始的带回卷搜索；
- 授权后更新下一轮起点；
- 无请求时保持指针；
- 四个持续请求者的轮流服务。

本阶段不验证：参数化请求者数量、接受握手、跨时钟域、形式验证、门级时序。

CDC = Clock Domain Crossing，跨时钟域。

## 3. 验证策略

- 使用定向测试明确控制请求和预期指针；
- 使用自检式 testbench 自动比较 `grant` 与预期值；
- 通过层次引用检查内部 `priority_ptr` 状态；
- 每个数据场景都检查 one-hot 和请求授权一致性；
- 通过错误注入确认检查器不是只能让正确实现通过；
- 使用固定命令运行，确保结果可重复。

## 4. 检查器

| 检查器 | 规则 |
|---|---|
| 复位检查 | 复位期间 `grant=0000` 且 `priority_ptr=0` |
| 结果检查 | 当前授权与场景预期一致 |
| 指针检查 | 上升沿后的指针与预期下一状态一致 |
| 独热检查 | `grant` 为全零或只有一位为 1 |
| 合法性检查 | `(grant & ~req) == 0` |

## 5. 场景覆盖

测试矩阵覆盖 21 项定向场景。当前阶段记录的是场景覆盖，不等同于工具统计的 functional coverage（功能覆盖率）。

## 6. 错误注入

将 `priority_ptr=2` 且请求者 3 获授权后的下一指针从 0 改为 1。预期 testbench 报告指针错误，并在后续场景捕获错误状态传播。

## 7. 退出标准

- 21 项测试全部通过；
- 没有非法授权或多重授权；
- 四请求持续有效时按 0、1、2、3 回卷；
- 稀疏请求能够跳过未请求者；
- 错误注入能够被现有检查器捕获；
- 仿真命令可以从干净目录重复执行。
