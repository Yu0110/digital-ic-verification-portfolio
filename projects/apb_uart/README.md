# APB 寄存器外设验证

**简体中文** | [English](README.en.md)

两个寄存器地址、可配置等待、错误响应、定向与随机自检、请求匹配、协议检查和功能覆盖统计。目录沿用规划名称 `apb_uart`，没有 UART 串口功能，也不是 UVM 类环境。

APB = Advanced Peripheral Bus，高级外设总线；RTL = Register Transfer Level，寄存器传输级；DUT = Design Under Test，被测设计。

## 从哪里看

先看 [完整流程与限制](docs/final_walkthrough.md)；最新独立构建结果见 [发布回归](reports/publication_regression.md)。

1. `spec.md`：外设应该做什么。
2. `rtl/apb_regs.sv`：被测寄存器模块。
3. `tb/apb_regs_tb.sv`：发送请求、计算期望、自动比较。
4. `notes.md`：写入时机和独立期望值。

## 运行

需要 Verilator、C++ 编译器、make 和 Bash。在本目录运行：

```sh
make test
make faults
make dut-faults
make lint
make wave
make roles
make protocol
make random
make regression
```

`test` 测试等待参数 0、1、3；每组必须出现 `APB_PASS`，并完成 20 笔传输。`faults` 故意启用提前写入错误，每组必须出现 `EXPECTED_FAULT_DETECTED`。错误版是人为注入，不是实际产品缺陷。

日志在 `build/<模式>/wait_<拍数>/run.log`，编译日志在同目录的 `compile.log`。波形在 `build/wave/wait_<拍数>/apb_regs.vcd`。

## 职责拆分练习（2026-09-24）

运行 `make roles`，阅读 `tb/apb_roles_tb.sv`：`submit` 先保存计划请求，`drive` 只驱动总线，独立监视进程捕获完成沿的快照，`match_request` 按顺序对应请求，`score` 按规格检查响应并维护期望值。每个等待配置观察 9 笔完成事务，等待拍不重复记录。

这是单文件、任务级的过渡版本，不是完整 class/UVM 分层环境。监视器同步调用记分板；复位分支清零参考状态。脚本还人为污染第二笔读响应，要求比较器准确报告实际 2B、期望 2A。

此版本只通过总线检查功能，不能替代原测试的内部提前写入检查。已用独立计划队列匹配地址、方向和写数据，并在收尾检查没有剩余请求。计划在驱动前保存，不能根据观察值反向生成。现已接入协议检查、可选随机请求及显式计数功能覆盖。

本轮 `make roles` 通过：三个等待配置共观察 27 笔完成事务；三个观察数据污染测试均命中指定读回错误。日志位于 `build/roles/wait_<拍数>/`。

范围审计和附加故障测试见 [完整流程](docs/final_walkthrough.md)。

`make roles` 还运行五种请求故障：地址错误、方向错误、写数据错误、漏发最后一笔和额外重发。错误只注入发送路径，原始计划保持不变。三个等待配置分别执行，每项要求命中特定请求错误标记。本版只在请求间复位；请求中途复位的取消匹配策略尚未实现，不能默默清空计划队列掩盖漏发。

## 协议检查

`tb/apb_protocol_checker.sv` 只读取总线，用过程式即时断言比较相邻采样点。它不是并发 `property` 版本。运行脚本强制启用 `--assert`。

`make protocol` 独立测试检查器，包括合法零等待、带等待、背靠背、读操作写数据变化、等待中复位，以及 10 个故意违规场景。负向测试必须非零退出且命中特定错误，不能把超时当作成功。

检查器已连接到职责拆分版。`make regression` 依次运行基础正向、提前写及四种附加电路故障、职责拆分及负向检查、协议正负向、随机覆盖回归和 RTL lint。任何一步失败，命令停止。

## 随机与覆盖

`make random` 运行 3 个种子 × 3 个等待配置，每组 200 笔随机请求加定向前后段共 219 笔。功能覆盖模型为 8 个方向与地址类别组合，加 3 个合法写数据类别，共 11 格；定向补齐前后分别报告。另有种子重放对比、缺覆盖拒绝测试。详情见 `docs/random_coverage.md`。

## 电路故障案例

正常运行时所有故障参数均为 0。提前写入由 `make faults` 验证，附加四种故障由 `make dut-faults` 验证。五种都属于主动注入的错误，不是真实产品缺陷。故障机理和对应检查见 [故障矩阵](bug_reports/dut_fault_matrix.md)。

范围：本项目单外设 APB3 信号集合；不覆盖多外设共享 PENABLE、字节选通、保护属性、所有未知态或采样沿之间的短脉冲。协议检查不替代数据记分板，也没有宣称完整协议覆盖。

## 基础版本边界

这是同步时序外设。内部只保存数据寄存器和等待计数；组合逻辑生成读数据、就绪和错误响应。输入输出见 `spec.md`。

测试在下降沿驱动，在上升沿判断是否完成，稍后检查寄存器更新。期望数据来自请求和规格，不从 DUT 读取答案；另用内部 `data_reg` 做白盒检查，发现准备或等待阶段提前写入。

基础测试本身不是分层验证环境；扩展版为任务级职责拆分和伪随机激励，没有 class 约束求解或并发协议 property。尚未验证任意等待参数及所有地址。普通寄存器重复写入相同值不易观察，不能据此宣称已证明所有副作用只执行一次。
